# Real-data validation — 2026-08-23/24

Physlint `0.1.0a0` established the baseline and `0.1.0a1` reran the release gate against four public, immutable LeRobot v3 snapshots from four producers. The evaluation covered 74 episodes, 31,258 frames, four embodiments, six video streams, and approximately 362 MiB of dereferenced source data.

## Method

1. Size each Hugging Face repository with `hf download --dry-run`.
2. Download the complete repository and record the returned snapshot SHA.
3. Run `physlint inspect` to verify discovery and inventory.
4. Run the default `physlint check` and write a JSON report.
5. Manually inspect every finding against Parquet values, actions, states, and cited video frames.
6. Copy the smallest source with symlinks dereferenced, inject one defect per copy, and rerun Physlint.

The Hugging Face cache and original dataset snapshots were read-only throughout testing. Raw JSON reports were written outside the repository because they contain machine-local absolute paths.

## Manual finding classification

All 67 findings on the unmodified rover snapshot were false positives under the default quality contract.

### Fixed 80 ms maximum gap: 50 false positives

The dataset declares 4 FPS and every cited timestamp delta is the expected 250 ms. `temporal.sampling_interval` correctly passes the same cadence. The fixed `temporal.max_gap` default of 80 ms therefore contradicts the declared sampling rate and floods the report at its 50-finding cap.

Classification: **confirmed Physlint false positive**.

Recommended change: derive the default maximum gap from declared FPS, for example `max(configured_absolute_limit, expected_interval * relative_multiplier)`, or require an explicit absolute limit for low-rate datasets.

### Frozen frames: 17 false positives

Every cited frozen-frame range occurred while all action components were zero. State remained constant except for small voltage/orientation changes. Contact-sheet inspection showed static scenes, not evidence of a stalled decoder or camera. The longest finding covered frames 42–141 of the front camera (25 seconds at 4 FPS); the scene and robot were stationary throughout.

Classification: **confirmed static-scene false positives; camera failure not established**.

Recommended change: do not enable this rule at error severity without a motion signal. Correlate frame repetition with action/state motion, require a much longer static interval, or report static-video evidence as a notice requiring review.

With `max_gap_ms: 300` and `video.frozen_frames` disabled, the unchanged rover snapshot passed all 13 remaining applicable rules with no findings or errors in 5.78 seconds.

## Controlled corruption baseline

Corruptions were injected into three separate, fully dereferenced copies of the clean Panda snapshot. Each test changed one source condition.

| Seed | Expected rule | Result | Additional expected evidence |
|---|---|---|---|
| NaN at episode 0, sample 5, state dimension 0 | `numeric.finite_values` | Detected at the exact episode/sample | `temporal.stream_overlap` also treats the NaN row as incomplete |
| Swap timestamps at rows 10 and 11 | `temporal.monotonic` | Detected at episode 0, sample 11 | Sampling-interval and maximum-gap findings locate the affected neighborhood |
| Delete source row 50 without changing metadata | `episode.valid_boundaries` | Detected for episode 0 | Sampling-interval and maximum-gap rules locate the missing sample |

Seeded-defect recall in this run: **3/3**. Clean-source regression for the same snapshot: **0 findings**.

## Baseline performance observations

Video decoding dominates execution:

| Dataset | Total rule time | Video-rule time | Share |
|---|---:|---:|---:|
| Rover | 11.60 s | 11.51 s | 99.3% |
| SO-101 | 164.94 s | 162.64 s | 98.6% |
| YAM humanoid | 187.73 s | 186.81 s | 99.5% |

Each of `video.decode`, `video.frozen_frames`, and `video.black_frames` currently opens and decodes the same streams independently. The freeze and black-frame implementations also perform full-resolution NumPy reductions before sampling.

Recommended change: create one shared decode pass per video stream, compute all enabled video observations together, and cache privacy-safe derived metrics. Spatially sample before color reduction. Do not start a 10 GB benchmark until this is addressed.

Peak memory was not recorded because the sandboxed macOS `/usr/bin/time -l` could not access the required system metric. Sample access remained batch-oriented, but bounded-memory behavior still needs a dedicated benchmark outside the sandbox.

## Product issues discovered

1. **P1 — FPS-aware gap defaults:** normal low-rate data fails at error severity.
2. **P1 — Static-scene handling:** frozen-frame findings need motion correlation or lower default severity.
3. **P1 — Shared video decode:** repeated decoding makes medium video datasets take minutes.
4. **P2 — Dataset identity:** reports use the snapshot-directory SHA as the dataset name when `info.json` lacks `repo_id`; accept an explicit source identity or infer it safely from Hub metadata.
5. **P2 — Finding aggregation:** one repeated condition can consume the 50-finding cap; group recurring cadence/static intervals and report affected counts plus representative evidence.
6. **P2 — Duplicate semantics:** NaN triggers both finite-value and stream-overlap rules. Decide whether this is useful corroboration or redundant noise.

## Fix verification

All six P1/P2 findings were addressed and the same immutable inputs were rerun. The default maximum-gap limit is now twice the declared frame interval unless an absolute `max_gap_ms` is explicitly configured. Frozen-frame evidence now requires motion in the first available configured motion stream (action before observed state by default). The video rules share one cached decode pass with spatial sampling before reductions.

Repeated maximum-gap and black-frame evidence is grouped into ranges, Hugging Face cache paths produce stable repository and revision fields, and NaN/Inf evidence belongs only to `numeric.finite_values` rather than also appearing as missing stream data.

| Dataset | Post-fix result | Applicable rules | Findings | Rule time | Before | Change |
|---|---|---:|---:|---:|---:|---:|
| `ViaCatalyst/robomimic-can-ph-lerobot-v3` | Pass | 11 | 0 | 0.197 s | 0.21 s | comparable |
| `cagataydev/scout-earth-rover-mini-20260616-053232` | Pass | 14 | 0 | 2.624 s | 11.60 s | 4.42× |
| `lerobot/svla_so101_pickplace` | Pass | 14 | 0 | 11.306 s | 164.94 s | 14.59× |
| `vikram-avea/sentinel-demo-09` | Pass | 14 | 0 | 13.003 s | 187.73 s | 14.44× |

The rover ranges were validated against their aligned values before suppression: action was exactly `[0, 0, 0]` across both remaining candidate ranges. Integer-valued observed sensors fluctuated by one or two units, which explained why an initial union of action and state motion still produced two false positives. Giving action precedence suppresses this sensor quantization while allowing users to configure state as the primary signal for observation-only datasets.

The three controlled corruptions were rerun after the fixes:

| Seed | Post-fix result | Relevant findings |
|---|---|---|
| NaN | Detected | One `numeric.finite_values` finding; `temporal.stream_overlap` passes |
| Swapped timestamps | Detected | Monotonic, sampling-interval, and grouped maximum-gap evidence |
| Deleted row | Detected | Episode-boundary and sampling-interval evidence |

Post-fix seeded-defect recall remains **3/3**. Clean-data results are **4/4 passing**, with no findings and no rule errors. Local verification also passes the test suite, Ruff, and strict mypy.

The immutable manifest, deterministic corruption recipes, sanitized JSON reports, CSV/JSON summary, and artifact SHA-256 values are committed under [`validation/`](../../validation/README.md). Generated corrupted dataset copies remain ignored because they are reproducible from the pinned source.

## Release recommendation

The P1/P2 release blockers found in this evaluation are resolved. The MVP is ready for a small public beta, provided the claims stay scoped to the evidence: LeRobot v3, these four pinned public datasets, 31,258 frames, and three controlled corruption classes. Keep these pinned cases as a release gate and add a larger, separately measured memory/performance benchmark before claiming broad production readiness.
