# MCAP and ROS 2 field validation — 2026-08-27

This validation gate combines three different kinds of evidence instead of treating generated fixtures as field proof:

- an upstream Foxglove MCAP conformance case;
- one revision-pinned, robot-captured ROS 2 MCAP episode from RobotisAI;
- controlled positive and negative ROS 2 recordings that exercise known rule outcomes.

## Robot recording

The public source is `RobotisAI/evButtonPush-arx5-260722-0-MCAP`, revision `0aed43ed01aa25f01267f8e384b28565ece6f18e`, file `0/0_0.mcap`. Its SHA-256 is `f99e990595e5570d63047bfa16c3edc71b5ce196f23e39613328588128206879`.

The source metadata describes a successful ARX X5 inference episode for pressing an elevator button. The rosbag2 metadata declares ROS 2 Jazzy, a 19.2-second MCAP recording, and 7,047 messages across joint state, target, compressed camera, TF, and gripper topic declarations.

Physlint auto-detected the ROS 2 profile and decoded all 7,047 recorded messages using the embedded schemas without a ROS installation. The configured field contract requires the six topics that contain data. Twelve applicable rules passed; cadence and header/log clock skew remained `not_run` because the source does not publish independent thresholds for those contracts.

## Bugs found by the field recording

The first run exposed two false-positive paths, both fixed before accepting the result:

1. A zero-message gripper topic and its schema are retained in the MCAP summary but absent from the data section. Summary consistency now compares Statistics counts with actual data-section declarations, not the broader summary maps.
2. A declared topic with zero messages no longer satisfies `ros2.required_topics`. Required means at least one recorded message.

Cadence checking was also narrowed to explicitly configured rates. Physlint no longer invents a stable-rate contract for event-driven ROS topics.

## Claim boundary

This is credible field evidence for an alpha, not proof of universal real-world accuracy. It demonstrates compatibility with one genuine ROS 2 Jazzy robot capture plus deterministic positive and negative cases. Split bags, SQLite `.db3`, application-specific messages, other ROS distributions, and a broader range of robots still require additional evidence.

The immutable manifest, reproduction harness, and sanitized reports are under [`validation/`](../../validation/README.md).
